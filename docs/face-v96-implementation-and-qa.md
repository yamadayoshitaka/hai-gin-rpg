# 顔品質v96：実装タスク、PR方針、開発者QA

## 対象と現象
『灰銀のレゾナンス』のWebGL「顔・髪の編集」画面の実3D顔。女性20代・普通/痩せ型/超痩せ型を優先し、男性・他年代への回帰を防ぐ。
ユーザーの実機画像では、大笑いのV字口裂、頬コケ、口紅消失、目の縁・アイラインの荒れ、横顔の鼻根から頬への不連続、歯と口腔の不自然さがある。

## 実装タスク（優先順位と状態）
### P0 — v96の改善コード
- [x] 口輪筋：幅方向51%の過剰な引き延ばしを撤廃。上唇/下唇、口角の広がり、顎開き、頬の上昇を分けた丸い開口形状へ変更
- [x] 頬：頬骨〜口角の中上部を軽く前方に支え、既存FACSの重複変形を緩和。若い顔の極端な法令線/暗い溝を軽減
- [x] 口紅：投影矩形だけでなく本来の口裂エッジループの実3D位置に沿った唇マスクを使用。実メッシュの色と粗さに反映
- [x] 目元：48分割の実まぶた追従ラインと、目頭/目尻への滑らかな幅ゼロテーパー。浮いた画像デカールは禁止
- [x] ESM整合：顔・表情・口腔・メイクのモジュールキャッシュIDを一致させ、ネイティブ口腔WeakMapの二重生成を防止
- [x] 構造回帰：口裂の楕円形・頬のボリューム・実唇の着色・アイライン端の連続性を自動テストに追加
- [ ] 画像評価：正面・45度・横顔の実機/WebGL画質は要レビュー。自動テスト成功だけで美術合格にしない

### P1 — 完全リトポロジー（継続課題）
- [ ] 目輪筋、鼻翼〜鼻根〜頬、口輪筋、ほうれい線周辺をアニメーション対応の連続したクワッドエッジループに再構築
- [ ] まぶた、赤唇縁、上下唇外周、口角〜頬への流れを独立ループ化し、UV縫合・法線・曲率連続を検査
- [ ] 肌・赤唇・口腔内壁・歯・舌を適切なPBR/SSS値に分離（口紅が表情で消えないこと）
- [ ] FACS形状キーを再設計：jawOpen、cornerUp、cornerOut、upperLipRaise、lowerLipDrop、cheekRaise、lowerLidCompress
- [ ] 顔全体を新高密度クワッドメッシュに切り替える前に、元モデルの保護、性別/年齢/髪/装備連携の回帰を通す

## GitHub PR向け修正方針
1. 現行main v95から専用ブランチを切り、元GLBを変更しない。画像の貼り直しではなく本当の3D頂点/材質/アニメーションを修正する。
2. すべての表情変形は非累積。ニュートラルへ戻した際、元の頂点と法線が復元されること。
3. 口角を極端に引くのではなく、上下唇と頬を協調させる。口裂はV字/逆三角にならないこと。
4. 口紅・薄いチーク・アイメイクは実3D表面へ追従。マテリアルの置換と髪の頭皮クリッピングの後にも維持する。
5. 年代・体型差を維持。20代で頬コケが悪化しないこと。男性・高齢の顔を無断で変更しない。
6. 顔/髪/WebGLテストに加え、正面・斜め45度・横顔（髪あり/なし）を保存して比較する。
7. 性能と公開前品質の検証を通していない場合はDraft PRのまま保持する。自動テスト合格≠2D参考画像品質。

## 開発者向けチェックリスト
### 造形
- [ ] 20代普通/超痩せ型で頬が骸骨状にえぐれない
- [ ] 鼻根→鼻梁→鼻翼→頬が正面・45度・真横で自然につながる
- [ ] 微笑み・大笑いで頬が上がり、口角に不自然なV字・鋭い折れ目が出ない
- [ ] 顎を開いても上下唇が丸い開口と厚みを保ち、歯/舌/内壁に貫通がない
- [ ] ほうれい線は法線・曲面で表現し、黒い浮遊線にならない
- [ ] 表情選択100回後も元位置・法線へ戻り、メッシュ反転/欠損がない
### 色・メイク
- [ ] 無表情・微笑み・大笑いの全てで自然な口紅の色と艶が見える
- [ ] 上唇・下唇と口角に余計な紫色の化粧板がない
- [ ] アイラインは目頭/目尻で自然に細くなり、まつ毛と重なって黒い板に見えない
- [ ] チーク・肌血色が頬の形状に追従し、20代の濃いクマ・深い法令線がない
- [ ] 歯は自然色、自然な歯列、笑顔でも上下歯が口腔から浮かない
### 表示・波及
- [ ] 正面、45度、真横 × 無表情/微笑み/大笑い × 髪あり/なしの18条件を確認
- [ ] 女性・男性、20代・60代、普通・超痩せ型のスライダー/保存データが壊れない
- [ ] 顔のワイヤー/カラー切替、頭皮の隠し処理で口紅・口腔アニメが消えない
- [ ] 顔/髪/WebGLのGitHub Actionsを実行し、実描画の画像Artifactを残す
- [ ] 戦闘・町・装備は変更しておらず、既存表示・アニメへの影響がない
- [ ] 公開時にはPR・CI・Pages反映状況を別々に報告する

## 受け入れ基準
P0コードの自動テスト成功と実際の3D画面での美術確認は別判定。2D参考に未到達なら「実装した」「修正コードは動いた」と表現し、「品質達成」「完成」とはしない。完全なリトポロジーには新しい高密度トポロジーモデルと再リギングが必要。
