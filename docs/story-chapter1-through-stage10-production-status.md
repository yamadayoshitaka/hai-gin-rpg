## 対象と重要な区別

- 第一章の物語ステージは `c01-s01`〜`c01-s10`。第1ステージの既存構成・原画はそのまま維持し、本作業では `c01-s02`〜`c01-s10` の男女・勝利/敗北/主人公戦死別マニフェストを整理する。
- 第2〜第10は各48の正本コマ、**9ステージで計432コマ**。新しく追加した第6〜第10が240コマ。100コマ単位なら **100＋100＋100＋100＋32 = 5バッチ、44シート**。
- 10コマあたり2列×5行、各コマ独立したWebPを2048×1152ピクセルで作るのが推奨。10コマ保管シートは4096×5760。直接そのサイズを画像生成器が出力する保証はない。
- **今回のマニフェスト/QA/CI/Pagesデプロイでは、生成AIによる新規高品質原画は作られない。** リポジトリの画像生成器接続は `false` であり、台本生成＝絵の完成とは扱わない。
- ステージ2の既存GitHub初稿15枚は未承認。第3〜第10の新規高品質原画として新たにコミット・検品済みの画像は、この台帳作業では0枚。未承認でゲーム表示に混ぜない。

## P0：原画の生成・審査ルール

- キャラクターの**実マスター画像のバイト列**を生成器へ必ず添付。プロンプトにパスを書いたのみでは未実装・`BLOCKED`。
- 文字・番号・吹き出し・セリフ・字幕・ルビ・ロゴ・ゲームUIを画像内に描かない。台詞と音声の確定読みは画像外のゲームデータへ。
- 男女混在、リュシアと女性主人公の混同、勝利前の勝利演出、戦死後の生存、イベント捏造を禁止。
- 人物同一性と台本内容、16:9・1536×864以上の実ネイティブ画素・SHA-256を確認。検査を通過していない画像を本番登録・公開しない。
- 100コマレビューシートは画像生成ではなく、**すでに存在する高解像度WebPを無拡大でロスレス合成・分割する方式**。画像未提供なら待機とし、過去の小型画像を大きくして完成扱いにしない。

## 実行と検証

```bash
node qa/story-chapter1-through10-production.test.mjs
node scripts/run-story-stage-range.mjs --start c01-s02 --through c01-s10
```

上の処理で第2〜第10の台本コンテクスト・人物参照・原画実体の有無・シート合成可否を検査する。すべて `NOT_APPROVED` を初期値とする。GitHub Actionsの `Story chapter 1 through stage 10 (P0 locked)` から成果物を取得できる。

**完了の定義：** 各原画の実体作成 → P0人物画像添付の証明 → 原画の人物・画質・台本目視合格 → コマ単位で登録 → ゲームで男女勝敗別を表示確認 → Pagesデプロイ。いずれか未了なら当該原画は完成扱いしない。
