# ウィッグ制作標準 v1（次回以降の新規制作・再構築は必須）

更新日: 2026-11-24
対象: 「灰銀のレゾナンス」の男女キャラクター用の**新規／再構築／修正ウィッグ**。女性v121の頭部を現行の基準とするが、男性モデルにも同等の計測規則を適用する。
目的: 外観品質を担保した**独立着脱GLBウィッグ**を安定して制作する。機械的QA合格 ≠ 見た目の承認。

## 最優先ルール

1. **頭部の実GLBを測定**する。頭部を球・楕円体とみなしてフィットさせない。眉、目、肌、顔メッシュは変更しない。
2. **基準座標と頭型を確定してから髪を制作**する。正面・右側面・背面・頭頂の基準画像を作成・比較する。
3. **外側の髪全体のバウンディングボックスだけでサイズ合わせしない。** 頭頂／毛根帯（crown）と毛先は別々に採寸し、髪型ごとの補正を使う。ポニーテールやロングは特に要注意。
4. **最初にシルエット**。髪型の前髪、横髪、後ろ髪、頭頂、襟足、結び目、テールの構造を分ける。髪の下に不自然な頭皮・穴・板・突起を残さない。
5. 高品質な毛束は、**ガイドカーブ → 先細り断面付きの実メッシュ → 必要に応じて薄いHair Cardsで毛流れ補助**。単純な円錐／太い帯／ランダムな板の寄せ集めだけで完成としない。
6. 既存の質のよいGLBをベースにする場合、**元の毛束・UV・テクスチャ・法線を壊さない**。CC0等のライセンス・配布元・改変可否を記録する。
7. **Blenderで作成・検査するのが標準**（実行できる環境では bpy / Geometry Nodes / Curve を用いた再現可能スクリプトを保存）。実行環境がない場合は「Blenderで検証済み」と主張しない。
8. **プレビューと本番の同一GLB**を使う。テストが通っただけで「修正完了」「品質改善済み」と言わず、画像と実機で外観検査する。
9. **性別・髪型ごとに別の当てはめプロファイル**。単一のグローバル倍率でボブ・ロング・ポニーテールを兼用しない。
10. 修正前後の比較を残す。**変更点・残る欠陥・GLBのソース・再現手順**を記録し、承認されていない見た目を成功扱いしない。

## 必須制作工程・ゲート

### G0: 基準・素材の固定（制作着手前）

- 元の頭部GLBのパス、バージョン、SHA、XYZ軸、単位、原点を記録する。
- 頭頂、頭囲、左右耳、額の生え際、側頭部、後頭部、襟足、肩・背中の当たりを**実メッシュ**から測定する。
- 既存の髪／新素材の出自・ライセンスを確認。**スキンヘッドの眉は残す**。顔を上書きしない。
- 顔／髪のルート座標を揃え、変換行列の掛け忘れや二重スケーリングがないことを確認。
- 出力: 頭部測定JSON、頭部4方向の比較画像、素材・ライセンス記録。

### G1: 形状（質感の前）

- 2D見本／明示的な目標がある場合、正面・側面・背面・頭頂の**シルエット一致**を最優先。
- 前髪 (fringe)、横髪 L/R、頭頂 (crown)、後ろ髪 (back)、襟足 (nape)、結び目／テールを**区別可能な構造**として制作。
- 頭皮へ密着したキャップは実頭部の表面に沿って作る。地肌の露出と大きすぎる帽子状の浮きを防ぐ。
- 前髪は額・眉の前面に適切な隙間を保ち、頭や額の裏に入り込ませない。耳・顔を不自然に貫通しない。
- カーブの髪流れ・根元・中間・毛先の幅／厚みを設計。束の先端は自然に先細りする。
- 髪型別プロファイルで頭頂／毛根帯を合わせ、毛先や長さはシルエットに従わせる。
- 出力: ソリッド表示4方向＋頭頂の画像。**ここで形が悪いならテクスチャ工程に進まない。**

### G2: 毛流れ・材質

- ガイドカーブから断面付き毛束メッシュを生成。根元接続部、頭頂の分け目、毛先を自然につなぐ。
- 大きな束の立体造形 + 微細なストランド用Hair Cards／テクスチャの**ハイブリッド**を基本とする（髪型と性能によりカード省略可）。
- UV、Base Color、Normal、Roughnessの適合性を確認。テクスチャの方向は毛流れに揃える。
- Hair Cards採用時はWebGL/Three.jsで透過ソート問題を起こしにくい**alpha MASK / cutoutを優先評価**。double-sidedや陰影の見え方も実機確認。
- 既存素材を加工する場合、毛流れテクスチャの解像度／品質を理由なく下げない。
- 出力: 通常光・逆光・暗部の比較画像。

### G3: フィット・衝突・アニメーション

- 頭頂・額・耳・頬・首・肩・背中への貫通、地肌露出、飛び出した孤立メッシュや三角形の破綻を検査。
- ボブ・ロング・ポニーテールで独立に装着検査し、男性にも該当モデルで再測定する。
- 頭部スライダーや体型が変化する場合、頭部メッシュから再採寸して頭頂／根元帯を補正する。
- 首回転、歩行、横向き、上向き、ポニーテールの揺れ等で干渉しないことを確認。静的ウィッグなら動的シミュレーションを**勝手に必須化しない**。
- 出力: 貫通検査レポートと装着4方向画像。

### G4: GLB/モバイル

- BlenderのカーブやGeometry Nodesはゲーム実行用に**実メッシュへ評価／変換**。必要な法線、UV、材質、テクスチャを保持してGLB出力。
- 不正座標 NaN/Inf、面積ゼロの面、不要な孤立片、想定外の巨大メッシュ、未参照画像、誤った軸・単位がないか検査。
- LOD0（近距離）、LOD1、LOD2はゲーム表示と性能の両面で確認。細部削減は品質とFPSの実測を見て行う。
- **本番読み込みと再エクスポートの往復テスト**。元GLBと出力GLBを混同しない。
- 出力: GLB、対応するBlender制作ファイル／再生成スクリプト（可能な場合）、監査ログ、端末プレビュー。

### G5: 見た目の承認／公開

- **正面・左側面・右側面・背面・頭頂**の5方向スクリーンショットを用意。
- スキンヘッド単独、ウィッグ単独、装着状態の3モードで検査。
- スマホ実機（Pixel系・WebGL）で3種以上の異なる髪型を表示し、拡大／回転／カメラ切替を確認。
- 頭皮、前髪の侵入、浮き、スパイク、残骸、サイズ、毛流れ、テクスチャ、陰影、FPSを見直す。
- 既知の外観不良があれば**不合格**。自動テスト成功だけで最終承認しない。ユーザーが実機で確認できるURL、適用されたコミット、デプロイ状態を提示。
- 変更の影響が頭部・体・戦闘へ波及しないよう回帰確認する。

## 開始時と終了時の機械的チェックリスト

制作を開始するエージェント／ChatGPTは、まず次を**毎回チェック**する。

- [ ] 実頭部GLBに基づく計測である
- [ ] 見本と4方向シルエットを定義した
- [ ] 頭頂／毛根帯と毛先を分けて扱う
- [ ] 前／横／後／頭頂等が管理できる
- [ ] 再現可能なカーブ→メッシュ／外部GLB加工手順がある
- [ ] UV・毛流れ・法線・テクスチャを維持した
- [ ] 頭・耳・顔・体の干渉を検査した
- [ ] 孤立メッシュ・不正ジオメトリを監査した
- [ ] GLB出力と本番描画を照合した
- [ ] 実機での外観品質チェックと承認待ち状態を明記した

**チェック不能／未実施の項目は「未検証」と明記し、G5承認済み扱いにしない。** UIやスライダー調整だけでメッシュ・トポロジー起因の欠陥を「修正完了」としない。

## 現実性と役割分担

**ChatGPT単独の一発自動生成で高品質を保証することはできない**。ChatGPTはBlender Python（bpy）／Geometry Nodesの再現可能な制作スクリプト、形状・UV・法線の自動監査、GLB出力、ゲーム側の装着補正を担当しやすい。一方、原画に似せた毛束の流れや絶妙なシルエット、横顔・頭頂の品質は視覚比較・繰り返し調整が必要。実際のBlender実行環境とレンダリング／実機確認を組み込んで初めて安定した制作パイプラインとなる。

**次回の依頼でこの手順を最初に読み、G0→G5を順番に実行すること。** 省略する場合は省略理由と品質リスクを明示する。
