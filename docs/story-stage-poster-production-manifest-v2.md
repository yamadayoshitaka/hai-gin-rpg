# 灰銀のレゾナンス｜ステージ別ポスター・個別原画マニフェスト v2（2026-11-13）

適用範囲：第一章ステージ2の残件・ステージ3全件を起点に、以降の全ステージ・男女・全勝敗／選択／協力／エンディング分岐へ順次適用する。既存の `docs/story-manga-artwork-production-contract.md` と `src/story-chapter-comic.js` の台本・画像ID・音声読みが正本。

## 1. 作業順序（必須）

1. **台本を確定**：`comicEditionsForStage(stageId)` から全版を列挙。各版の `comicForStage` の台本、主人公性別、ステージ状況、前後／勝利／敗北／戦死、選択肢、固有の人物ID、音声用読みを固定する。画像数を恣意的に前後5コマ等に減らさない。
2. **全パターンの「連続ポスター（原画シート）」を用意**：版×性別ごとに最大10コマの2列マスターを構想・制作。最初は全体の構図・人物・時系列を連続画像として提示。広告ポスター、仕様表、完了報告、ダッシュボードを作らない。初回以後は同じポスターを毎回提示せず、単独原画を個別納品する。
3. **男性版の単独原画を1コマずつ制作**：ポスター各セルを `shotId` に対応付けて切り出し。ただし小さいポスターの単純切り出し／拡大は高精細合格と見なさず、1536×864以上の単独原画として描き直す。構図を保ち、前後の連続性を維持する。次に同じ順序で女性版を制作する。
4. **流用候補を明記**：既存の同一台本ID・同一世界状態の画像を「利用予定」に登録する。ただし自動流用はしない。登場人物が実際に写っていない景観・物証等に限り、男女別の登録先へ別々に複製できる。コピー元のID・版・SHA256、主人公不在の根拠、確認者を必ず記録。勝利→敗北／戦死、異なるステージ／別事件、主人公の性別が違う人物画は流用禁止。
5. **流用不可のコマだけ新規作画**：人物・舞台・勝敗の不一致、画質不足、同じ見た目の反復、画像内文字の混入は再描画。女性版は主人公だけを変更し、リュシア、ガラン、イリス等は変更しない。
6. **品質審査・実ファイル登録・デプロイ**：各単独WebPに合格基準画像を並べて提示し、台本／人物／構図／16:9／文字なし／画質／性別／結果／音声・ID／SHA256／前後連続性を判定する。合格原画とポスターの実データを登録し、コードと画像のQA→PR→mainマージ→GitHub Pages成功と実ゲーム表示まで確認する。失敗・未承認ならそのステージは完了扱いにしない。**1ステージの全分岐が合格したら次ステージへ**。

## 2. 合格基準画像の運用

- **比較元画像を必ず表示する**：各コマの納品画面／レビュー表は「合格基準の参照画像」と「今回の候補画像」を並べる。現時点の仮参照は `assets/story/chapters/c01/panels/c01-s01-m02-male.webp`／`...-female.webp` と、人物ごとの実マスター。**既存ステージ1の原画も人間合格済みとは限らない**ため、仮参照を勝手に `APPROVED` と記録しない。
- 基準画像が未承認ならその事実を明記。レビュー済みの基準画像とSHA256を登録してから「合格基準」として使う。基準画像そのものに数字・文字・UIが含まれる場合も不採用。
- **画質下限**：個別原画は最低1536×864、16:9。2列×N行のフル解像度ポスターなら最低3072×(864×N)であり、横1182px等の一覧絵を切っただけでは足りない。WebPの実体・SHA256を確認し、アップスケールのみは `RESOLUTION_ONLY_NOT_QUALITY_APPROVED`。
- **描画**：第一ステージと同等以上の顔・髪・衣装・指・装備・建築・光・陰影・奥行き、全コマ同じ作品として統一。場面の必要物は台本通り。背景、人物配置、視線、時刻の不自然な変化を却下。
- **厳禁**：文字、数字、コマ番号（「04」等）、題名、字幕、セリフ、フリガナ、透かし、UI、ポスター用見出し、確認画面、ゲームのスクリーンショット、時系列と違う戦果、異性主人公の混入。画像内に文章を生成しない。字幕とVOICEVOXは原画外。
- 自動検査は寸法・破損・同一ファイル重複・シーン順・ファイル一致を検証する。**人物同一性、文字なし、画質の良否は画像を目視で確認して判定する**。機械検査だけで合格済みにしてはいけない。

## 4. 無料バッチ処理

追加課金が発生する生成APIは自動呼出ししない。`node scripts/prepare-story-stage-posters.mjs --start c01-s02 --count 2` で台本から男女・全分岐のポスター／個別原画制作指示書と不足一覧をJSONとしてまとめ、GitHub Actions `Story stage poster batch (free preflight)` の成果物に保存できる。画像が実際に生成されない場合は `MISSING` のままとする。

1ステージ完全合格→コミット→Pagesデプロイ確認→次ステージ、の順番を崩さない。無料Actionsの処理時間・外部無料生成枠には上限がある。**無償生成モデルが未接続ならバッチで実行できるのは台本抽出・再利用候補抽出・検査・画像配置候補まで**であり、作画したことにはならない。

### 無償バッチ実体化の仕様

高解像度WebPポスターの元ファイルが投入されると、Actionsが **2列×全行を1コマずつ正確に切り出し**、実WebP、SHA256、台本ID、暫定合格基準画像との左右比較用HTML、手動審査待ちJSONを成果物へ保存する。画像が無ければ `MISSING_SOURCE_POSTER` で終了し、架空の画像を作らない。低解像度のシート（1コマ1536×864未満）を切り出して合格扱いにすることは禁止。レビュー用成果物から実ゲームへの自動コピーはしない。人間の画質合格、各分岐の最終QAが完了したファイルだけ、既存の公開工程で昇格させる。
