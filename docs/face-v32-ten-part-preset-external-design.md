# 灰銀のレゾナンス — 顔モデル v32 3D部品選択 外部設計

## 目的と達成境界
- 全身女性モデル画面および男女顔編集画面からモーフスライダーを通常非表示にし、パーツの候補選択を基本操作とする。
- 男女それぞれ**顔立ち・目・鼻・口・髪・化粧の6カテゴリ×10候補=60設定、男女合計120設定**。
- 120設定は独立して手でスカルプトした120個の外部GLBファイルではない。既存の実頭部メッシュから別個の三角形メッシュを生成する、型指定されたプロシージャル3Dモデルである。
- 旧保存GLBとテスト用パラメータスライダーを互換用に保持し、通常のスマホ画面には表示しない。テスト用URLのみ `?qa=legacy`。

## UI 操作
各カテゴリ: 01〜10選択。目／鼻／口／髪には必要な位置（左右／上下／前後）と角度（-12, -6, 0, 6, 12度）を**ドロップダウンで選択**。輪郭・化粧はタイプのみ選択。

UI状態 → `resolvePartSelection(gender, choice)` → ベース設定＋局所形状パラメータ → 所有する顔メッシュの再生成 → 視点維持 → （必要なら）着脱ウィッグ再生成。眼球の独立スケール入力なし。

## 頂点メッシュ同化（自動フィット）
原本CC0ヘッドを破壊しない `geometry.clone()` に対して：
1. 頭部正規化座標系のランドマーク：両眼窩、鼻根・小鼻・鼻先、口角・口唇、頬・顎。
2. ガウス重みで対象周辺の元顔頂点を変形。移動・回転・前後量が外周でゼロへ連続的に収束し、境界の継ぎ目を作らない。
3. `computeVertexNormals()` で法線を再計算。眼球・まぶた・虹彩・口唇は同じ新しい顔表面をサンプルして追従。
4. 鼻は独立した浮遊球ではなく元の肌メッシュそのもの、口紅とアイシャドウも実顔／まぶたメッシュの材質・頂点色で表現。
5. 顔と体の結合は既存の頸部ブリッジを保持。頭部を再生成しても首の閉鎖処理を再適用。

## 髪
- 一束あたり独立した幅を持つ**4層のヘアカード／断面8頂点**。頭皮からの位置と毛束の接線法線をもとに幅・厚み・色調を変え、束内に空間的な前後差を作る。
- スタイル10種は分け目、根元の方向、前髪の流れ、長さ、頬沿いのボリューム、毛先の揺らぎ静止形状に差を付ける。
- スマホでの物理演算は引き続き無効（0Hz）。静的な造形段階で頭皮・顔・胴体との交差を補正。
- 性別ごとにスタイルの長さを変え、女性は長髪中心、男性は短髪〜ミディアム中心。
- スマホ用全身画面の描画密度は1・3・10倍。

## 保存／読み込み
- 選択した男女パーツの固有IDをGLB顔ノードのextrasに保持。実際のモデル頂点データも保存。これにより部品IDを復元可能にする基盤を用意。
- UIの候補と実際のパーツの生成コードは `src/face-part-catalog-v32.js` を単一の定義源とする。
- 保存済みv8顔原本はそのまま保持し、v31までのスライダーは`?qa=legacy`の回帰検査専用。

## 品質ゲート
- 全候補ID・タイプ定義の重複がない
- 男性・女性の顔頂点、目、唇の変更が実際にメッシュを変化させ、原本は保持される
- 4層ヘアカードの頂点数と厚み、静的0Hz、既存の髪・体衝突を保つ
- Android相当ビューポートのWebGL実描画、左右角度、GLBエクスポートを通す
- **美少女・美少年らしさ、自然な髪の品質は自動テストで保証できない**。実描画画像と実機での美術判定が必要
