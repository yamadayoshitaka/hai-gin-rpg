# 召喚獣・モンスター 3D 品質向上 実装指示書

対象：灰銀のレゾナンス / Android WebGL（将来の100〜1000体の軍団戦を含む）

## 1. 作品上の品質目標

- **最終ルック**：FF系の高品質な人間モデルと一緒に置いても質感・骨格・材質が浮かないファンタジーキャラクター。ライトニング等の商用キャラクターは**品質の参考**とし、固有の顔、衣装、テクスチャ、形状を複製しない。
- **シルエット**：全50体に違うID・色だけでなく種族の顔貌、角、翼、尾、脚、装飾があること。
- **顔**：眼窩、まぶた、頬、鼻、口角、顎、側頭部、耳の根元、首筋を複数の視点で検証。笑顔／詠唱／被弾でも破綻させない。
- **動作**：遊泳、T字固定、浮き、脚の停止、関節の分離、床貫通、射撃方向の反転を禁止。種族に沿った歩行・攻撃を優先する。
- **質感**：写真由来のカラー微細構造、ノーマル、roughness、金属／布／革／皮膚のPBR分離。材質ごとのsource/author/license記録を必須とする。

| 項目 | 現状 | 次の作業 |
|---|---|---|

| 極小ポリゴン粒度 | 制作原型/source と high/low を生成 | 実際の source→low リトポロジー・ベイクに置換 |

| 接合 | 四足獣・鳥・人型の首と肩にテーパー継ぎ目／接地修正 | 法線連続、実測骨格、スキニングの両方を自動チェック |
| 天使 | 羽根の曲率・分割・覆い羽・写真系繊維マップ | 実際の羽毛PBR、法線ベイク、翼関節のIK・空気抵抗 |

**重要**：プロシージャル原型を高密度に再分割しても、AAA水準の顔や動物解剖、写真品質が自動で生まれるわけではない。要点となる頭骨、関節、主翼、布を個体別に正しくスカルプトする制作工程が別途必要。

## 3. 召喚獣の実装タスク

### 守護天使（最優先）
- □ 女性／男性人体の顔を肌・眼窩・唇・耳・襟に分解し、接合部の位置と法線を整える
- □ 顔の写真系skin/albedo・normal・roughnessの整合を確認し、まぶた／虹彩／角膜を独立材質にする
- □ 翼を主羽→副羽→覆い羽の層にする。羽根の根元を翼骨に固定し、クローズアップで継ぎ目を確認
- □ 回復・蘇生・急降下・翼展開・ダメージの動作から肌／ローブ貫通を排除
- □ source（制作原型）→retopo→bake→高品質LODへ転写して同じ見え方を担保

### 森の精霊弓士
- □ 人体の頭骨と鼻梁・顎・目の位置を先に修正
- □ 尖った耳の付け根を頭皮側へ埋め込み、頭骨法線と色の不一致を排除
- □ リアル髪GLBの骨と額ラインを合わせ、髪が目・眉を貫通しないようにする
- □ 弓／弦／指／矢の各アタッチメントを分離、射撃時の向き・接触・矢の発射点をテスト
- □ 衣装の革・布・金属をマスク分割してPBRを適用

### 竜王・古竜・天竜・飛竜
- □ 頭骨と首の連続断面、口内・牙・舌・顎関節をスカルプト
- □ 鱗の大型輪郭を実メッシュ、微細情報を実写系 normal に分ける
- □ 翼膜の厚さ、翼骨、尾椎、飛行・着地、ブレス・薙ぎ払いを検証
- □ カメラ至近で体格や脚接地が破綻しないようにする

### 灰狼・軍馬
- □ 獣の肩甲骨・骨盤・趾／蹄の関節方向・歩幅を生体に合わせる
- □ 毛皮は個別の写真系 normal とカード毛で表現、風による変形は近景のみ
- □ 加速／減速、停止姿勢、騎乗時の鞍・脚・手綱の接触を回帰確認

## 4. モンスター50体：系統別作業

全てのID・名称・属性は `src/monster-catalog.js` が正。各系統5体の差分は法線マップや色だけで済ませない。

| 飛行 | 羽軸／主羽／覆い羽／爪 | 翼長、羽先、クチバシ、尾羽、炎／霧 |

| 昆虫 | 頭胸腹／関節／甲殻／薄翅 | 顎、角、甲虫殻、翅、金属色 |
| 蜘蛛 | 8脚の関節／腹部／複眼 | 毒針、腹模様、目、剛毛、巣 |
| アンデッド | 頭骨／歯／腐食布／鎧 | 霊魂、骨露出、腐食、面頬、髑髏装飾 |

| 水棲 | 吸盤／鱗／鰭／粘液 | 透明度、触手、波紋、外殻、珊瑚 |

### 50体の制作単位

1. 10体の原型をsource品質で制作・検証。構造と見た目を固定。
2. 各原型から4体ずつ変異を作り、固有部位の形状差と材質差を作成。
3. 全50体を idle / walk / run / attack / special / roar / dodge / hit / leap / defeat で鑑賞。
4. 原型と最適化済みの high / low を正面・横・斜め・背面で自動比較。
5. 戦闘配置やドロップ設定は図鑑とは別のランタイム機能として実装。

## 5. 素材・ライブラリの扱い

実際に読み込む素材は `src/monster-photo-pbr.js` 内で明示。**今回追加した新規写真ファイルはない**。そのため、新しい素材を入れる場合は別に原本・ライセンス・著作者・入手URL・色空間・マップ構成を記録する。

| 候補 | 使い方 | 権利確認 |
|---|---|---|
| Quaternius Universal Base Characters | 天使・エルフの人体ベースとリグ | 同梱CC0（`assets/characters/quaternius-base/base-license.txt`） |
| Poly Haven | 岩・皮革・金属・自然素材、HDRI | 原則CC0。素材単位のURLと取得日を記録 |
| ambientCG | stone, leather, fabric, fur系などのPBRマップ | 原則CC0。素材単位のURLと取得日を記録 |
| 既存 `assets/creatures/` | 狼毛皮、竜鱗のalbedo＋normal | 同梱の出所情報を確定するまで再配布ライセンスは未判定 |
| 既存 `assets/textures/outfits/` | 麻・革・鋼鉄・ベルベットなど | 同上 |
| Mixamo / Rokoko / Sketchfab / Fab / Megascans | リグ・参考モーション・候補素材 | **素材ごとに利用規約確認**。CC0と一括判断しない |

**写真系PBRの品質条件**：原本サイズ・UV繰返し・色空間、Base Color（sRGB）と Normal/Roughness/Metallic/AO（non-color）の区別を確認する。AOは`uv2`が必要。実測スキャンでないテクスチャを「写真」と偽装しない。

## 6. Source → Runtime最適化ルール

| LOD | 用途 | 実装段階 | 必須条件 |
|---|---|---|---|
| source | 制作用マスターメッシュ、頭部と骨格の精密検査 | v4.4.79から切替可能 | 実機戦闘では**利用しない** |
| high | 至近距離の図鑑・ボス・主要召喚獣 | v4.4.79 | PBR・破綻のないボーン・PC/Android用予算 |
| low | 遠距離・群衆 | v4.4.79 | シルエットが識別でき、highより十分軽い |
| ultra-low/instanced | 100〜1000体戦闘 | 未実装（モンスター側） | GPUインスタンシング・可視範囲・更新間引き |

現行LODはパラメトリック形状の**解像度別再生成**。まだ真のリトポロジー・UV転写・高密度→低密度ノーマルベイクではない。次段階でBlenderのバッチパイプラインを構築する。
