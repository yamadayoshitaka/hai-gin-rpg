## v3 必須仕様：コマの実寸と「1コマごとの台本追従」

**漫画原画は、固定した実サイズで、台本を毎回読み直して1コマずつ生成する。** 低解像度のポスターを切り抜いただけで本番原画として登録しない。

| 用途 | 実ピクセル・比率 | 品質判定 |
|---|---|---|
| **ゲーム本番の独立した1コマ** | **1536×864px以上・16:9横長・WebP（推奨2048×1152）** | 各画像の実画素・ネイティブな顔や装備の情報量・台本を独立検証 |
| 8コマ：2列×4行の保管シート | 3072×3456px以上 | 合格した8枚を合成し、低解像度の原画は拒否 |
| 7コマ：2列×4行の保管シート | 3072×3456px以上 | 8番目の空きセルを架空の場面で埋めない |
| 戦死後2コマ：2列×1行 | 3072×864px以上 | 戦死を生還・勝利へ改変しない |
| 最初に見せる連続構図ラフ | 低解像度も可 | 確認専用、本番への切り出し・アップスケール転用は禁止 |

画像生成の**毎回の指示**に「横1536×縦864px以上、16:9、推奨2048×1152、WebP」を明記。指定より小さい、比率が違う、引き伸ばしただけの画像は **SIZE_REJECTED**。顔・手・重要物証は四辺から**5%以上内側**（1536×864では左右約77px、上下約43px）に収める。画像内の文字・数字・コマ番号・台詞・ルビ・ロゴ・UI・透かしは厳禁。

**シナリオ → 分岐別全コマの順序確定 → ラフポスター → 現在の1コマの正確な台本と前後コマの台本を取得 → 実マスター画像を参照入力に添付 → 1枚だけ高精細制作 → 現在の台本と見た目を照合 → 合格した前コマ画像を次コマの参照に追加 → 次のコマ → 最後に本番シートを合成。**

1. コマ直前に性別・戦闘結果・選択・協力・エンディングを確定した comicForStage の当該台本を読み込む。現在のセリフ/行動、話者、登場人物ID、表情、舞台、勝利条件、結果をその**コマ専用の生成プロンプト**へ入れる。前後のコマは連続性のためだけに参照し、未来の勝利等を先取りしない。
2. 女性主人公（金髪ロング・青い目・銀鎧）、男性主人公（黒髪）、リュシア（銀髪摂政）、ガラン（老騎士）、イリス（治癒師）の**実画像バイナリ**を生成器に入力し、ファイル名だけで参照したことにしない。登場しない人物を無理に描かない。
3. 最新の**品質承認済みの同一分岐の前コマ原画**を継続性参照とする。未承認の前コマ・暫定人物マスターは暫定と明記し、勝利版・敗北版・戦死版間の流用禁止。
4. 完成候補の1コマごとに、現在の台本・人物容姿・シナリオ順・勝敗・16:9・1536×864実画素・顔/髪/装備の細部・安全域・文字無しを検品。合格基準画像は候補画像と並べて提示。実画像・両参照画像のSHA256・レビュー結果を記録。**単なるJSON生成を作画・品質合格と主張しない**。

制作コード scripts/prepare-story-stage-posters.mjs はすべての版と性別の各コマに imageSpec、generationPrompt、narrative.previousScene/currentScene/nextScene、requiredCharacterReferences、voiceText を出力する。この段階では画像生成APIの呼び出しも実画像添付も実施しない。実際の作画・検品・コミット・ゲーム登録・デプロイは別工程。

## 1. 作業順序（必須）

1. **台本を確定**：`comicEditionsForStage(stageId)` から全版を列挙。各版の `comicForStage` の台本、主人公性別、ステージ状況、前後／勝利／敗北／戦死、選択肢、固有の人物ID、音声用読みを固定する。画像数を恣意的に前後5コマ等に減らさない。
2. **全パターンの構図ラフポスター**：版×性別ごとに最大10コマの2列で台本と時系列を確認。ラフは本番へ切り出さず、完成した独立原画から最後に高精細シートを作る。
3. **男性版を各コマの台本に追従して単独制作**：毎回そのコマの台本・前後コマ・戦闘結果・性別・実キャラ参照を生成器へ渡し、独立した1536×864以上・16:9の原画を描く。ラフポスターを切り出して完成扱いにしない。次に主人公だけ女性へ変え、同じ方式で女性版を制作する。
4. **流用候補を明記**：既存の同一台本ID・同一世界状態の画像を「利用予定」に登録する。ただし自動流用はしない。登場人物が実際に写っていない景観・物証等に限り、男女別の登録先へ別々に複製できる。コピー元のID・版・SHA256、主人公不在の根拠、確認者を必ず記録。勝利→敗北／戦死、異なるステージ／別事件、主人公の性別が違う人物画は流用禁止。
5. **流用不可のコマだけ新規作画**：人物・舞台・勝敗の不一致、画質不足、同じ見た目の反復、画像内文字の混入は再描画。女性版は主人公だけを変更し、リュシア、ガラン、イリス等は変更しない。
6. **品質審査・実ファイル登録・デプロイ**：各単独WebPに合格基準画像を並べて提示し、台本／人物／構図／16:9／文字なし／画質／性別／結果／音声・ID／SHA256／前後連続性を判定する。合格原画とポスターの実データを登録し、コードと画像のQA→PR→mainマージ→GitHub Pages成功と実ゲーム表示まで確認する。失敗・未承認ならそのステージは完了扱いにしない。**1ステージの全分岐が合格したら次ステージへ**。

## 2. 合格基準画像の運用

- **比較元画像を必ず表示する**：各コマの納品画面／レビュー表は「合格基準の参照画像」と「今回の候補画像」を並べる。現時点の仮参照は `assets/story/chapters/c01/panels/c01-s01-m02-male.webp`／`...-female.webp` と、人物ごとの実マスター。**既存ステージ1の原画も人間合格済みとは限らない**ため、仮参照を勝手に `APPROVED` と記録しない。
- 基準画像が未承認ならその事実を明記。レビュー済みの基準画像とSHA256を登録してから「合格基準」として使う。基準画像そのものに数字・文字・UIが含まれる場合も不採用。
- **画質下限**：個別原画は最低1536×864、16:9。2列×N行のフル解像度ポスターなら最低3072×(864×N)であり、横1182px等の一覧絵を切っただけでは足りない。WebPの実体・SHA256を確認し、アップスケールのみは `RESOLUTION_ONLY_NOT_QUALITY_APPROVED`。
- **描画**：第一ステージと同等以上の顔・髪・衣装・指・装備・建築・光・陰影・奥行き、全コマ同じ作品として統一。場面の必要物は台本通り。背景、人物配置、視線、時刻の不自然な変化を却下。
- **厳禁**：文字、数字、コマ番号（「04」等）、題名、字幕、セリフ、フリガナ、透かし、UI、ポスター用見出し、確認画面、ゲームのスクリーンショット、時系列と違う戦果、異性主人公の混入。画像内に文章を生成しない。字幕とVOICEVOXは原画外。
- 自動検査は寸法・破損・同一ファイル重複・シーン順・ファイル一致を検証する。**人物同一性、文字なし、画質の良否は画像を目視で確認して判定する**。機械検査だけで合格済みにしてはいけない。

## 4. 無料バッチ処理

追加課金が発生する生成APIは自動呼出ししない。`node scripts/prepare-story-stage-posters.mjs --start c01-s02 --count 2` で台本から男女・全分岐のポスター／個別原画制作指示書と不足一覧をJSONとしてまとめ、GitHub Actions `Story stage poster batch (free preflight)` の成果物に保存できる。画像が実際に生成されない場合は `MISSING` のままとする。

1ステージ完全合格→コミット→Pagesデプロイ確認→次ステージ、の順番を崩さない。無料Actionsの処理時間・外部無料生成枠には上限がある。**無償生成モデルが未接続ならバッチで実行できるのは台本抽出・再利用候補抽出・検査・画像配置候補まで**であり、作画したことにはならない。

### 無償バッチ実体化の仕様

高解像度WebPポスターの元ファイルが投入されると、Actionsが **2列×全行を1コマずつ正確に切り出し**、実WebP、SHA256、台本ID、暫定合格基準画像との左右比較用HTML、手動審査待ちJSONを成果物へ保存する。画像が無ければ `MISSING_SOURCE_POSTER` で終了し、架空の画像を作らない。低解像度のシート（1コマ1536×864未満）を切り出して合格扱いにすることは禁止。レビュー用成果物から実ゲームへの自動コピーはしない。人間の画質合格、各分岐の最終QAが完了したファイルだけ、既存の公開工程で昇格させる。

## v4 ステージ専用マニフェスト：1ステージ＝1バッチ

**第1章ステージ2** の正本は `assets/story/stage-manifests/c01-s02.manifest.json`。男性/女性 × 戦闘前・勝利後・敗北後・主人公戦死後の **8版・48コマ** を台本ID順に固定する。勝敗・性別の混同、欠番、台本更新に伴うID不一致があれば失敗扱いで停止する。

### 1回の実行でステージ単位の制作処理

`node scripts/run-story-stage.mjs --stage c01-s02`

またはGitHub Actions「One-stage story production batch (free)」から stage_id=`c01-s02` を指定。1回の呼び出しで全版の現行台本、コマの前後文脈、人物画像入力指示、無文字の高精細ポスター用プロンプト、既存素材の有無、分割、比較、未承認のレビュー台帳まで処理する。1回のバッチ＝1回の画像生成とは違い、内部では版ごとに別々の原画が必要。

### 原画に番号や制作報告が描かれる不具合への強制制約

- **画像のピクセルに描くのは物語世界内の絵だけ。** タイトル、章見出し、字幕、コマ番号、画像番号、日本語、英数字、ダッシュボード、宣伝ポスター、黒帯のキャプション、表、UI、吹き出し、ロゴ、ウォーターマークを厳禁とする。羊皮紙、地図、紋章、封蝋にも読める字形は描かない。
- **番号・台本本文・シーンIDなどは画像から完全に分離したJSONに保管。** 旧い「番号付き場面一覧」のテキストを画像生成向けの本番プロンプトとして使わず、各版・各コマの正確な台本だけを演出上の参考として渡す（画像内には印字しない）。
- ポスターは **2列×4行（最大8場面）**。1コマのネイティブ原画1536×864px以上。戦闘前8コマ：3072×3456px以上、勝利/敗北7コマ：3072×3456px以上で8つ目は空欄、戦死後2コマ：3072×864px以上。画像全体の台本・人物・勝敗・文字混入を人間が検証する。
- **48コマを1枚の画像に押し込まない。** 4列×12行なら最低6144×10368px（約6370万画素）必要で、通常の画像生成解像度では一コマが小さくなり過ぎる。**ステージ単位の1バッチの中で8種類の原画シートを処理**する。
- 男女・勝敗・戦死の別版の映像は流用禁止。ただし主人公が写らない完全同一の景観・証拠物は、人物と状況の目視照合後に別名で流用できる。
- キャラクターの実マスター画像バイナリを生成器に添付する。テキストにファイルパスを書いただけでは固定できない。
- 合格条件：各場面の台本、勝敗、人物、画像内文字ゼロ、独立したネイティブ解像度、16:9、顔/衣装細部、余白、実ファイルSHA-256、人間の目視レビュー。失格なら差し戻し、本番への自動昇格は行わない。

### 実際に生成できる範囲

この無料GitHub Actionsには画像生成AIの実行APIは接続されていない。**既存の高解像度シートの取り込み・切り出し・比較・台本チェックは一括実行できるが、何も無い状態から48枚を自動作画することはできない。** 原画を `assets/story/chapter-drafts/c01/posters/` に配置しない限り `MISSING_SOURCE_POSTER` として止め、画像を生成済みと報告しない。高解像度原画が入力されても目視承認と公開は別工程。

ステージ2が品質承認・画像本体登録・ゲーム内表示・Pages公開まで完了してから、ステージ3の専用マニフェストを同様に作成して進む。
